    Part 0 · Orientation

    What we're building

    Does watching short-form video (SFV: TikTok / Reels-style clips) change how well people hold things in mind, their visual working memory (VWM)?

    Two ways to vary "how much video"

    • Duration block: one clip of 0 s (none), 5 s, 45 s or 120 s
    • Dose block: the same 45 s as one long clip or as three short ones (or none)

    What we record

    • Memory-task accuracy right after each video
    • Ratings: how much they want more, how much they liked it
    • What they remember about the videos afterwards

    Why include a no-video control condition in each block?

    Answer

    It's the baseline. Without it we couldn't tell whether a video helps, hurts, or does nothing: we'd only know how the video conditions compare with each other.

    You don't need the full reasoning for today; the design document (SFV_VWM_Design_Spec_Draft.md in the project's experiment/ folder) has it. Today is about how to build it.

    Part 0 · Orientation

    One session, start to finish

    Instructions→ Practice→ Block A→ Break→ Block B→ Memory tests→ Save & goodbye

    Part 0 · Orientation

    The one new idea: things with dots

    PsychoPy gives you objects: a square, a window, a keyboard. You use them with a dot:

    square = visual.Rect(win, width=0.1, height=0.1)   # make a square
square.pos = (0.25, 0)       # attribute: a setting you can read or change
square.draw()                # method: something it can DO (note the parentheses)
win.flip()                   # the window is an object too
    • No parentheses (square.pos): a value you can look at or set.
    • Parentheses (square.draw()): an action. Do it now.
    • You never write the class yourself; PsychoPy already did. You just use the objects.

    In square.pos = (0.25, 0), is pos an attribute or a method?

    Answer

    An attribute: no parentheses, and we're setting it, moving the square.

    Part 1 · The memory task

    Change detection in one minute

    +
    Fixation0.6 s
    →
    +
    Sample0.25 s
    →
    +
    Blank delay1.0 s
    →
    +
    Testuntil D / S
    (max 3 s)

    Did anything change? D = different  ·  S = same

    On half the trials one square changes to a new color (above: green → orange). On the other half nothing changes.

    Why is there a blank delay between the sample and the test?

    Answer

    That's the "working memory" part: the colors have to be held in mind with nothing to look at. Without the delay it would just test whether you can see.

    Settings first: what the squares look like

    # --- the memory task (change detection) ---
SET_SIZE = 4                       # PROVISIONAL: squares per array
COLORS = {                         # name -> (R, G, B), each 0-255
    "red":     (220, 40, 40),
    "green":   (40, 170, 70),
    "blue":    (50, 90, 220),
    "yellow":  (240, 210, 40),
    "magenta": (200, 60, 190),
    "cyan":    (40, 190, 200),
    "orange":  (240, 130, 30),
}
SLOTS = [(-0.25, 0.25), (0, 0.25), (0.25, 0.25),      # places a square may appear
         (-0.25, 0),               (0.25, 0),         # (3x3 grid without the center,
         (-0.25, -0.25), (0, -0.25), (0.25, -0.25)]   #  which is where the + goes)

    SET_SIZE: the design doc says 3 squares, but 3 is probably too easy for change detection (everyone near 100%). We'll pilot to choose. It's a setting, so changing it is one number.

    Part 1 · Section 4 · The memory task

    Decide everything about a trial first

    def make_trial(is_change):
    """Decide everything about one trial before showing anything."""
    slots = random.sample(SLOTS, SET_SIZE)             # which places are used
    sample_colors = random.sample(list(COLORS), SET_SIZE)   # which colors (all different)
    test_colors = sample_colors.copy()
    changed_item = None
    if is_change:
        changed_item = random.randrange(SET_SIZE)      # which square will change
        spare = [name for name in COLORS if name not in sample_colors]
        test_colors[changed_item] = random.choice(spare)
    return {"slots": slots, "sample_colors": sample_colors, "test_colors": test_colors,
            "is_change": is_change, "changed_item": changed_item}
    • random.sample(list, 4) picks 4 different items. list(COLORS) is the list of color names.
    • spare = colors not in the array, so the changed square becomes a genuinely new color.

    What would go wrong if we wrote test_colors = sample_colors (no .copy())?

    Answer

    Both names would point at the same list. Changing test_colors would also change sample_colors, so the "change" would appear in both arrays and nothing would ever look different.

    Part 1 · Section 4 · The memory task

    Draw all the squares, then flip once

    def draw_array(slots, color_names):
    for square, slot, name in zip(squares, slots, color_names):
        square.pos = slot
        square.fillColor = COLORS[name]
        square.draw()
    • zip(a, b, c) walks through several lists in step: square 1 with slot 1 with color 1, then square 2 with slot 2 …
    • Inside the loop we only move, recolor, and draw. Nothing is on screen until the win.flip() that the caller makes.

    Why make the caller flip, instead of flipping inside draw_array?

    Answer

    We also want the fixation cross on the same screen. If draw_array flipped by itself, the + would need a second flip: a different moment. One screen = one flip = one exact onset time.

    Part 1 · Section 4 · The memory task

    One trial (1/2): fixation, sample, delay

    def run_trial(trial, feedback=False):
    # fixation, with a little random jitter so the start can't be predicted
    fixation.draw()
    win.flip()
    core.wait(FIXATION_TIME + random.uniform(0, 0.1))

    # the sample array
    draw_array(trial["slots"], trial["sample_colors"])
    fixation.draw()
    win.flip()
    core.wait(ENCODING_TIME)

    # the blank delay: the participant has to HOLD the colors in memory
    fixation.draw()
    win.flip()
    core.wait(RETENTION_TIME)

    Same rhythm every time: draw → flip → wait. The feedback=False is an optional argument we'll use in Part 2.

    core.wait() is accurate to about one screen refresh (≈ 17 ms on a 60 Hz screen). Fine for learning. For real data collection, labs usually count frames instead (e.g. 15 frames ≈ 250 ms). Worth doing before the real study.

    Part 1 · Section 4 · The memory task

    One trial (2/2): the test and the response

        # the test array, and start the RT clock at the exact moment it appears
    draw_array(trial["slots"], trial["test_colors"])
    fixation.draw()
    win.callOnFlip(kb.clock.reset)
    kb.clearEvents()
    win.flip()
    keys = kb.waitKeys(maxWait=MAX_RESPONSE_TIME, keyList=list(KEYS) + ["escape"], waitRelease=False)

    if keys is None:                                   # nothing pressed in time
        response, rt, correct = None, None, 0
    elif keys[0].name == "escape":
        quit_experiment()
    else:
        response = KEYS[keys[0].name]                  # "s" -> "same", "d" -> "different"
        rt = keys[0].rt
        truth = "different" if trial["is_change"] else "same"
        correct = int(response == truth)

    return {"response": response, "correct": correct, "rt_s": rt}
    • callOnFlip(kb.clock.reset): start the RT clock on the flip, when the test array really appears (as in Workshop 2).
    • truth = "different" if … else "same": what the right answer is. correct is 1 if the response matches it.

    Part 2 · Many trials

    Half change, half no-change

    def balanced_trial_list(n):
    """n True/False flags, half 'change' and half 'no change', in random order."""
    flags = [True] * (n // 2) + [False] * (n - n // 2)
    random.shuffle(flags)
    return flags
    • [True] * 8 is a list of eight Trues. n // 2 is division that drops the remainder (7 // 2 is 3).
    • random.shuffle(flags) reorders the list in place, with no = needed.

    Why do we want equal numbers of change and no-change trials? And what does balanced_trial_list(5) give?

    Answer

    If 80% of trials changed, pressing "different" every time would score 80% with zero memory. Balanced trials make guessing worth 50%.

    balanced_trial_list(5) → 2 True and 3 False, shuffled. An odd number can't split evenly, which is why we use 16 trials per condition and not 15.

    Part 2 · Many trials

    Why we save what was true, not just "correct"

    They press D (different)They press S (same)
    Something changedHit ✓Miss ✗
    Nothing changedFalse alarm ✗Correct rejection ✓
    • Someone who says "same" to everything gets 50% right, but with zero hits. Accuracy alone hides that.
    • Hit rate and false-alarm rate together separate real memory from a habit of answering one way. This is the idea behind signal detection theory.
    • So every row saves is_change (the truth) and response (what they said). The analysis can work out everything else.

    This is also how the memory tests for the videos (Part 4) are scored: pictures they saw are "changes" in the same sense, pictures they didn't see are "no change".

    Part 2 · Many trials

    Run a set of trials, save a row for each

    def run_trials(block, condition):
    for number, is_change in enumerate(balanced_trial_list(TRIALS_PER_CONDITION), start=1):
        trial = make_trial(is_change)
        result = run_trial(trial)
        trial_rows.append({
            "participant": info["participant"],
            "block": block,

            "trial": number,

    • enumerate(..., start=1) gives a counter (1, 2, 3, …) alongside each item.
    • "-".join(["red", "blue"]) → "red-blue": a list squeezed into one CSV cell.

    Part 3 · Reward videos

    Find the clips, pick some

    def find_clips(bucket):
    return sorted((VIDEO_ROOT / GENRE / bucket).glob("*.mp4"))


def choose_clips(plan):
    """plan = [(bucket, seconds), ...]  ->  [(clip file or None, seconds), ...]"""
    used = []
    picks = []
    for bucket, seconds in plan:
        options = [clip for clip in find_clips(bucket) if clip not in used]   # never repeat a clip
        clip = random.choice(options) if options else None    # None = no file on this computer
        used.append(clip)
        picks.append((clip, seconds))
    return picks
    • Path / "folder" joins paths. .glob("*.mp4") lists every matching file; sorted makes the order predictable.
    • for bucket, seconds in plan unpacks each pair. if clip not in used keeps the three 15 s clips different.
    • If a folder is empty or missing, options is empty and we get None. The script then shows a stand-in screen instead of crashing, so you can build and test without the big video files.
    Part 3 · Reward videos

    Play a video (1/3): fit it to the screen

    def fit_in_box(width, height, box_width, box_height):
    """Biggest size that fits inside the box without stretching the picture."""
    scale = min(box_width / width, box_height / height)
    return (width * scale, height * scale)

    Our clips are a mix: some vertical (1080 × 1920, like a phone), some horizontal (3840 × 2160). One rule handles both:

    • Work out how much each side would have to shrink to fit, and take the smaller shrink (min). Both sides then fit, and the shape isn't distorted.
    • The screen is 1 unit tall and win.size[0] / win.size[1] units wide (≈ 1.43 in our test window).

    A 1080 × 1920 clip in a box 1.43 wide and 1 tall. Which side limits it: width or height?

    Answer

    Height: 1 / 1920 is smaller than 1.43 / 1080. The clip becomes 0.56 wide and 1.0 tall, with grey bars either side, like a phone video on a laptop.

    • A while loop: draw one frame, flip, repeat until movie.isFinished. Each pass is one screen refresh.

    • "Get ready…" first, because the load can take a few seconds for a 120 s clip, and without it the participant stares at a frozen screen.

    Many online examples (and older code) wait with while movie.status != FINISHED. In PsychoPy 2026.1 that value never updates, so the loop never ends. Use movie.isFinished.

    Part 3 · Blocks

    Counterbalancing: alternate which block goes first

    def block_order_for(participant):
    """Even-numbered participants do Duration first, odd-numbered do Dose first."""
    digits = "".join(ch for ch in participant if ch.isdigit())     # "P007" -> "007"
    number = int(digits) if digits else 0
    return ["duration", "dose"] if number % 2 == 0 else ["dose", "duration"]
    IDdigitsnumberfirst block
    P002"002"2 (even)duration
    P003"003"3 (odd)dose
    test""0 (even)duration
    • number % 2 is the remainder after dividing by 2: 0 for even, 1 for odd.
    • Why counterbalance? Whatever block comes first gets a fresh, un-fatigued participant. Alternating spreads that evenly across the two blocks.

    Why work the order out from the ID, instead of random.choice?

    Answer

    It's reproducible (you can re-derive anyone's order from their ID if a file goes missing) and it alternates exactly. Coin flips could easily give 7 of one kind and 3 of the other.

    def still_path(clip, tag):
    return STILL_ROOT / clip.parent.parent.name / clip.parent.name / f"{clip.stem}_{tag}.jpg"


def pick_foils(shown):
    """For each clip they watched, a clip from the same folder that they did NOT watch."""
    foils = []
    for clip in shown:
        options = [c for c in find_clips(clip.parent.name) if c not in shown and c not in foils]
        foils.append(random.choice(options))
    return foils


def build_test_items(shown, foils, tag):
    items = [{"image": still_path(clip, tag), "is_old": True, "shown_in": shown_in[clip]} for clip in shown]
    items += [{"image": still_path(clip, tag), "is_old": False, "shown_in": (None, None)} for clip in foils]
    return items
    • Old = from a video they watched. Foil (also called a "new" item) = from a video they did not, chosen from the same folder so it looks similar.
    • Each item is a small dictionary. shown_in remembers which block and condition an old picture came from, so we can later ask "did people remember the 120 s video better than the 5 s one?"
    • This needs Image in the imports (from PIL import Image, already at the top of our file). It reads a picture's real size so we don't stretch it.
