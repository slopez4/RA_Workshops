    Part 0 · Python in 5 minutes

    Variables & lists

    # Anything after a # is a comment: a note for humans
n_participants = 20             # a variable stores a value
task_name = "reward task"       # text goes in quotes
print(task_name, "has", n_participants, "participants")

rts = [512, 634, 598, 2950, 101]   # a list holds several values
len(rts)    # how many? -> 5
max(rts)    # biggest   -> 2950
rts[0]      # FIRST item -> 512   (Python counts from 0!)

    Two of those reaction times look suspicious. Which ones, and why?

    Answer

    101 ms is too fast to have seen the stimulus and responded (an anticipatory press). 2950 ms means they were probably distracted.

    Part 0 · Python in 5 minutes

    Loops & if-statements

    for rt in rts:
    if rt < 150:
        print(rt, "-> too fast")
    elif rt > 2500:
        print(rt, "-> too slow")
    else:
        print(rt, "-> looks OK")
    • for repeats the indented lines once per item.
    • if / elif / else pick one branch.
    • Lines ending in : start a block.
    • Indentation (4 spaces) is the grammar. It's how Python knows what's inside.
    Part 1 · Bring the data in

    Load a file in one line

    import pandas as pd              # pandas: tables ("Excel inside Python")
import matplotlib.pyplot as plt  # matplotlib: plots

df = pd.read_csv(DATA_URL)   # df = "data frame" = a table
df.head()                    # first 5 rows
df.shape                     # (rows, columns)
df["participant_id"].value_counts()   # rows per participant

    What does one row represent: a participant, a block, or a trial?
    20 participants × 4 blocks × 20 trials = ? Does it match df.shape?

    Answer

    One row = one trial. 20 × 4 × 20 = 1600, and df.shape is (1600, 8) ✔. Every participant has 80 rows. Always check the counts add up.

    Part 1 · Codebook

    The (fake) reward experiment

    A two-choice task in 4 blocks of 20 trials. Reward blocks earn points for fast, correct answers. Block order is counterbalanced.

    columnmeaning
    participant_idP01–P20
    orderreward_first or no_reward_first
    block · trialblock 1–4 · trial 1–20 within block
    conditionreward or no_reward
    rt_msreaction time in ms (empty = no response)
    correct1 = correct, 0 = wrong or missed
    motivation_rating1–7, asked once per block, copied onto every row of that block
    Part 2 · Look before you analyze

    Can I trust this data?

    df.describe()          # min, max, mean, count of every numeric column
df.isna().sum()        # missing values per column

df["rt_ms"].hist(bins=60)   # how are the RTs spread out?
plt.xlabel("Reaction time (ms)")
plt.show()
    • What are the min and max of rt_ms? Are they believable?
    • Why is the count for rt_ms smaller than for the other columns?
    Answer

    Min 81 ms (impossible), max 5944 ms (zoned out). Count is 1579 vs 1600 → 21 missed responses with no RT. RTs are skewed right, which is typical.

    Part 2 · Look before you analyze

    Is anyone just guessing?

    # groupby = sort rows into piles (one per participant), then compute for each pile
# the mean of a 0/1 column = proportion correct = accuracy
acc_by_participant = df.groupby("participant_id")["correct"].mean()
acc_by_participant.sort_values()

    Does anyone stand out? With two buttons, what accuracy would guessing give you?
    Why decide what to do about it before looking at the results?

    Answer

    P07 ≈ 49%; everyone else is 80–94%. Guessing gives 50%, so P07 was probably not doing the task.
    If you drop people after seeing how they affect the result, you can make the data say almost anything.

    Part 3 · Clean the data

    Keep only the rows you trust

    too_fast = df["rt_ms"] < 150        # True/False for every row
too_fast.sum()                       # True counts as 1 -> how many?

excluded = acc_by_participant[acc_by_participant < 0.60].index.tolist()

clean = df[
    ~df["participant_id"].isin(excluded)   # ~ means NOT
    & (df["rt_ms"] >= 150)                # & means AND
    & (df["rt_ms"] <= 2500)
].copy()
    What we found

    24 trials < 150 ms · 21 trials > 2500 ms · excluded P07 · 1600 → 1458 rows.

    Part 3 · Thinking about data

    Every cleaning step is a decision

    • Write the rule, not the name. "Below 60% accuracy," not "drop P07." Rules still work when new data arrive, and readers can see what you did.
    • Decide before you see results. Otherwise it's too easy to (even unintentionally) pick the exclusions that give the answer you hoped for.
    • Know what your code silently does.

    We never wrote a line to remove the missing RTs, but they're gone. Why? Is that right when we compute accuracy?

    Answer

    An empty cell is not >= 150, so the comparison is False and the row is dropped. That's fine for RT (there is no RT), but for accuracy a missed response is arguably an error. The same rule can be right for one measure and wrong for another.

    Part 4 · Does reward change behavior?

    One number per person first

    clean.groupby("condition")[["rt_ms", "correct"]].mean()   # quick look

# Better: average within each participant, so everyone counts equally
per_person = clean.groupby(["participant_id", "condition"])["rt_ms"].mean().unstack()
per_person["reward_effect"] = per_person["reward"] - per_person["no_reward"]

(per_person["reward_effect"] < 0).sum()    # how many were faster with reward?

    unstack() turns the condition labels into columns, like a pivot table.

    What we found

    Reward 598 ms / 91.5% vs no-reward 645 ms / 86.7%. Faster and more accurate, so it isn't just trading accuracy for speed. 17 of 19 participants were faster with reward.

    Part 4 · Does reward change behavior?

    Plot individuals, not just means

    for pid, row in per_person.iterrows():            # one gray line per person
    plt.plot(["no_reward", "reward"], [row["no_reward"], row["reward"]],
             color="gray", alpha=0.5, marker="o")

plt.plot(["no_reward", "reward"],                  # group mean on top
         [per_person["no_reward"].mean(), per_person["reward"].mean()],
         color="black", linewidth=3, marker="o")
plt.show()

    Does everyone show the effect? What does this plot tell you that a single average can't?

    Answer

    Most lines go down, 2 go up, and the size of the drop varies a lot. An average of −47 ms can hide people who show no effect at all.

    Part 5 · Does the effect change over time?

    Is reward as powerful at the end as at the start?

    half_of_block = {1: "1st half", 2: "1st half", 3: "2nd half", 4: "2nd half"}  # a dictionary
clean["half"] = clean["block"].map(half_of_block)                              # look up each row

by_half = clean.groupby(["participant_id", "half", "condition"])["rt_ms"].mean().unstack()
by_half["reward_effect"] = by_half["reward"] - by_half["no_reward"]

ratings = clean.drop_duplicates(["participant_id", "block"])   # 1 rating per block, not 20

    Wrap-up

    From notebook to script

    Everything we ran, in order, is an analysis script. analysis.py is the same code, tidied:

    1. Settings: every decision at the top
    2. Load
    3. Check
    4. Clean
    5. Analyze
    6. Plot

    5 habits that matter more than syntax

    1. Check the numbers add up.
    2. Look at distributions before averages.
    3. Set exclusion rules before results, and write them as rules.
    4. Summarize per participant, then across.
    5. Plot individuals, not just means.
